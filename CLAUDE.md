# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Live Resume: a single-page personal resume/portfolio built with Angular 21 (the LTS line; TypeScript 5.9, Zone.js change detection). It ships in two locales (en, pt) and uses Firebase for the contact form and analytics. Node `^20.19 || ^22.12 || ^24` is supported; `.nvmrc` pins Node 24.

## Commands

```bash
npm ci                              # clean install from the lockfile; no --force / --legacy-peer-deps needed
npm run start:en                    # dev server on :4200 in English (start:pt for Portuguese)
npx ng serve -o --host 0.0.0.0 --configuration en   # README's way to serve, reachable from other devices
npm run build                       # default build -> dist/live-resume (add -- --configuration production for budgets)
npm run build-locale                # production-style build of both locales -> dist/en, dist/pt
npm run lint                        # ng lint (angular-eslint, flat config in eslint.config.js)
npm run validate:posts              # check src/assets/data/posts.json (schema, en+pt, ≤275-char descriptions)
npm run validate:context            # check src/assets/data/assistant-context.txt (the AI answers' notes)
npm run test:rules                  # check firestore.rules in the Firestore emulator (needs firebase-tools and Java)
npm --prefix functions ci           # install the Cloud Functions package (functions/, separate lockfile)
npm --prefix functions run typecheck && npm --prefix functions test   # strict tsc + vitest, model stubbed, no paid calls
npm --prefix functions run build    # esbuild bundle -> functions/lib (+ the CV data in lib/data)
npm --prefix functions run deploy   # build and deploy the functions (needs firebase-tools and access)
npm test -- --watch=false --browsers=ChromeHeadless   # Karma + Jasmine unit specs (core pipes/services)
npx ng test --include src/app/path/to/file.spec.ts    # run a single spec
npm run test:e2e                    # build both locales, then run the Playwright browser suite (e2e/)
npm run test:e2e:run                # rerun the browser suite against the existing dist/ output
npm run test:e2e:docker             # build the Docker image, run it on :8080 and run the browser suite against it
docker build -t live-resume . && docker run --rm -p 8080:80 live-resume   # serve http://localhost:8080/en/ and /pt/
npm run int:extract                 # regenerate src/locales/messages.xlf (ng extract-i18n)
```

**Browser suite (required gate before every commit).** `e2e/resume.spec.ts` runs Chromium at desktop and mobile (Pixel 7) viewports against the localized production builds served by `e2e/serve.mjs` on `http://127.0.0.1:4300/{en,pt}/` (`E2E_PORT` overrides the port). `e2e/fixtures.ts` stubs Firebase/gtag bootstrap calls, reCAPTCHA and the App Check token exchange, aborts Firestore writes and blocks all other third-party traffic, and fails a test on console errors, page errors or failed first-party requests. Output goes to `test-results/` (HTML report, landing screenshots per locale/viewport in `test-results/screenshots/`, traces/screenshots on failure). First run needs `npx playwright install chromium`. CI (`.github/workflows/ci.yml`) runs `npm ci`, lint, `validate:posts`, `validate:context`, unit tests, the functions package (install, typecheck, tests, bundle), the production build and `npm run test:e2e`.

**Docker.** `Dockerfile` builds both locales in a `node:24-slim` stage that is discarded, and the runtime image is `nginx:1.30-alpine-slim` with only the static files (no Node); `docker/nginx.conf` redirects `/en` and `/pt` to `/en/` and `/pt/`, serves each locale's `index.html` for extension-less paths under it, returns 404 for missing files and for anything outside the locale prefixes. `e2e/serve.mjs` follows the same contract, and `E2E_BASE_URL` points the browser suite at any running server (the container via `npm run test:e2e:docker`).

**Releases.** Pushing a tag `vX.Y.Z` runs `.github/workflows/docker-publish.yml`: it fails unless the tag equals `package.json`'s version, runs `npm run test:e2e:docker`, then pushes `docker.io/guilhermeborgesbastos/live-resume` for linux/amd64 + arm64 as `X.Y.Z`, `X.Y`, `X`, `latest` and `sha-<commit>` (pre-releases only `X.Y.Z-…`). Bump the version with `npm version X.Y.Z --no-git-tag-version` in a PR and update CHANGELOG.md before tagging. Needs the `DOCKERHUB_TOKEN` secret (`DOCKERHUB_USERNAME` variable optional). PRs touching the image run the workflow without pushing.

`deploy.sh` builds both locales, stages `dist/<locale>/browser/<locale>/` as `dist/site/<locale>/` plus a root `dist/site/index.html` (a copy of the English one with an absolute `og:image`, served at https://guilhermeborgesbastos.com/), then empties the S3 bucket `www.guilhermeborgesbastos.com` and uploads each locale to its `en/` / `pt/` prefix (served as https://guilhermeborgesbastos.com/en/ and /pt/) and the root `index.html`, then invalidates `/*` on each CloudFront distribution listed (space-separated) in the required `CLOUDFRONT_LIVERESUME_DISTRIBUTION_ID` env var (checked before building): `E2FO2ELLS8J6VG` and `E14O8X5D7XL2SZ`, one per domain (apex and `www.`). It is destructive and must not be run during development; `./deploy.sh --stage-only` builds and stages without touching S3. The script stops before touching S3 if the build fails or a locale's `index.html` is missing. `DEPLOYMENT.md` covers the AWS setup (CLI, the deploy-only IAM policy, the `live-resume` profile) and the deploy checklist. AWS only hosts the static site: the assistant's AI answers run on Firebase (`firebase.json`, `.firebaserc`, `functions/`) and deploy separately with `npm --prefix functions run deploy`, before `deploy.sh` when the CV data changed (the function bundles its own copy); see "AI answers (Firebase)" in `DEPLOYMENT.md`. Firestore security rules live in `firestore.rules` (only the contact form's `contacts` create is allowed; everything else, including the assistant's `assistantConfig`/`assistantUsage`/`assistantRate`, is denied) and deploy with `firebase deploy --only firestore:rules`, which replaces the console's rules; edit the file, not the console, and run `npm run test:rules` after any change.

## Architecture

**One page, many sections.** `AppRoutingModule` routes `""` to `ResumeComponent` and `/assistant` to the lazy CV assistant page; `/about`, `/experience`, `/posts`, `/contact` redirect to fragments (`/#about`, etc.) and everything else goes to the standalone 404 component. After a fragment navigation `ResumeComponent` keeps the target section in view while the data-driven sections render (up to 2 s, until the visitor scrolls). `ResumeComponent` stacks the section components (welcome, about, experience, posts, contact, footer) and tracks scroll/visibility through `appInViewport` (`core/directive/on-viewport.directive.ts`) to set the header's `activeSection`.

**Content lives in JSON, not in templates.** `core/data.service.ts` loads `src/assets/data/{about,experiences,posts}.json`. Each record has an `internationalizations` array of per-language objects (`language: "en" | "pt"`). Templates render those fields with the `appInternationalization` directive (`[data]="item.internationalizations" property="description"`), which picks the entry matching `LOCALE_ID` and writes it via `innerHTML` — so JSON strings can contain HTML. When editing resume content, update both the `en` and `pt` entries. New posts are added with the `add-post` project skill (`.claude/skills/add-post/`, documented in `docs/add-post-skill.md`): every title/description goes through `humanizer:humanizer`, and `scripts/posts.mjs add` inserts the record newest-first; don't hand-edit `posts.json` for new posts.

**Two i18n mechanisms coexist:**
- Static UI strings use Angular `@angular/localize` (`i18n="meaning@@id"` attributes) with translations in `src/locales/messages.{en,pt}.xlf`. The `en`/`pt` build configs set `i18nMissingTranslation: "error"`, so a new `i18n` attribute without entries in **both** xlf files breaks the localized build. Source locale is `en-US`.
- Dynamic content uses the JSON `internationalizations` arrays described above.

**Modules.** `main.ts` bootstraps `AppModule` with `platformBrowserDynamic` and `provideZoneChangeDetection()` (the app is not zoneless). Components, directives and pipes are standalone but are composed through NgModules (`ResumeModule`, `PostsModule`, ...); `CoreModule` provides `DataService`, `SorterService`, HttpClient, and exports shared pipes/directives (localized/Safari-safe date pipes, ellipsis, i18n and viewport directives). Dependencies use `inject()`, templates use built-in control flow (`@if`/`@for`), and `strictTemplates` is on. The 404 page is lazy-loaded via `loadComponent`.

**CV assistant.** `src/app/assistant/` holds a deterministic Q&A over the three JSON files that runs in the browser, plus optional hosted AI answers for the questions it can't answer (updating its data: `docs/ai-assistant-data.md`). The pure engine (`engine/`, `knowledge/plain-text.ts`, `knowledge/knowledge-adapter.ts`) validates the data into a frozen snapshot with JSON pointers, matches whole questions against the reviewed EN/PT forms in `engine/question-patterns.ts`, resolves slots only to existing records (reviewed aliases in `resolve-question.ts`), and composes answers from `engine/answer-templates.ts` with a `SourceRef` per record; anything else returns the fallback. Near-miss or ambiguous names return `clarify` with verified canonical questions (never an answer), and explicit follow-ups (`CONTEXT_PATTERNS`) use the latest answer's single-experience `subject` as context. Never add CV facts to code, and extend it by adding a pattern, an evidence check, a template and EN/PT fixtures in `engine/assistant-engine.spec.ts`. The root `AssistantSessionService` (in-memory, 50-pair cap) is shared by the floating panel (`ui/launcher` + `ui/panel`, a modal `<dialog>`, shown only while About/Experience/Posts is active) and the `/assistant` page. Citations link to `/?experienceId=<id>#experience` and `/?post=<url>#posts`, which `ExperienceComponent`/`PostsComponent` read after their data loads. Assistant UI strings use `assistant@@assistant.*` IDs; `src/localize.d.ts` declares `$localize` for code.

**Hosted AI answers (off unless `environment.assistantHosted.enabled`).** When the engine returns an `unrecognized`, `unknown-entity` or `no-results` fallback (`api/hosted-answer.ts`), the session adds a `pending` pair and `api/hosted-answer.service.ts` calls the `askAssistant` callable with a single-use App Check token (one request at a time; Clear drops late replies; the visitor's "Answer only locally" switch stops it). The function (`functions/src/core/`, entry `functions/src/index.ts`, body in `core/handler.ts`) first rejects a replayed App Check token (`request.app.alreadyConsumed`) and resolves the visitor's IP from the right of `X-Forwarded-For` by `TRUSTED_PROXY_HOPS` (`core/client-address.ts`; unresolvable = refused), then `core/ask.ts` checks a Firestore kill switch (`assistantConfig/runtime.enabled`, missing = off), validates the request (`models/hosted-answer.models.ts`, shared), compares `knowledgeVersion`, and in one Firestore transaction checks the daily/per-visitor limits and reserves the call's cost ceiling against the monthly budget. It then makes one Claude Haiku 5.5 call on the Claude API (`core/model.ts`, `ClaudeApiAnswerModel`, key in the `ANTHROPIC_API_KEY` secret) with a JSON schema whose evidence IDs are a closed list, runs the grounding checks in `validate-answer.ts`, and settles the reservation to the actual cost (an unknown cost keeps the reservation). Prices come from `core/pricing.ts` (`TARIFFS` per Claude API model, injected as a `CostPolicy`; a model without a price fails `onInit`). Log events, outcomes, limits, check names and Firestore paths are enums in `core/constants.ts`, the shared result kinds are enums in the models (`HostedResultKind`, `UnavailableReason`, `HostedAnswerKind`): don't add string literals for them. The prompt names the CV owner from `environment.prod.ts` `personal.name`/`firstName`, never from code. Logs never hold question or answer text. The model reads `knowledge/evidence-map.ts` text (stable IDs such as `exp.6.tech`, `post.<hash>`, `ctx.<note-id>`), built from the JSON plus `src/assets/data/assistant-context.txt` (owner-written EN/PT notes, public, parsed by `knowledge/assistant-context.ts`, read by the function only). Generated text is plain text with its own `HostedAnswer` types and an "AI-generated" label; citations are rebuilt in the browser from the cited evidence IDs (notes render as labels without a link). The shared modules under `knowledge/`, `engine/` and `models/` must stay free of Angular: the function bundles them with esbuild. Facts go in the JSON or the notes file, never in code or prompts.

**Carousels and swipe.** Experience and posts carousels extend `core/shared/abstract.swipe.section.ts`, implementing `onClickPrevious/onClickNext` and the `disable*Navigation` guards; HammerJS swipe config lives in `AppModule`. Post cards fade in with an `animate.enter` CSS class; leaving cards are removed at once (no `animate.leave`), because a fade-out kept both pages in the flex row and made the section jump on mobile. The deprecated `@angular/animations` package is not used.

**Firebase.** The modular `firebase` SDK is used directly (no AngularFire). `core/firebase.ts` provides the `FIREBASE_APP` token initialized from `environment.firebaseConfig`; `contact/contact.service.ts` lazily imports Firestore and writes to the `contacts` collection, after starting App Check (`core/app-check.service.ts`, shared with the assistant's AI answers, which start it when the assistant opens) with the reCAPTCHA Enterprise provider, aka Google Cloud Fraud Defense (`environment.recaptchaSiteKey`, a score-based Enterprise key, since App Check no longer registers reCAPTCHA v3 keys; empty disables it and the AI answers) when the visitor first focuses the form; the reCAPTCHA badge is hidden in `styles.scss` and replaced by the `recaptchaNotice` text under Send; setup and enforcement order are in `DEPLOYMENT.md`; `core/analytics.service.ts` (started by `AppComponent`) lazily initializes Analytics outside the Angular zone and logs a `screen_view` per navigation. Personal details (name, birth date, email, location, caricature image) are in `src/environments/environment*.ts`; `environment.prod.ts` is swapped in for production builds.

**Styling.** Each component typically has a `*.scss`/`*.css` plus a separate `*.responsivity.*` file for breakpoints. Production budget for component styles is 6kb warning / 10kb error.
